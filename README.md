# Hierarchical RAG

A simple retrieval-augmented generation (RAG) prototype for understanding hierarchical RAG, taking the use case of answering questions about academic calendars stored as PDF files.

This project uses a **two-level retrieval pipeline**:
1. **Document-level retrieval** using LLM-generated summaries of each PDF
2. **Chunk-level retrieval** within the most relevant documents

The final answer is then generated by an OpenAI model using the retrieved context.

## What this project does

Given a folder of academic calendar PDFs, the script:

- extracts text from each PDF
- generates a short summary for each document
- embeds document summaries for top-level retrieval
- chunks each document into smaller pieces
- embeds chunks for fine-grained retrieval
- answers natural-language questions using retrieved context

The implementation is designed around questions such as:
- “When was NUS Well-Being Day in Semester 1 of academic year 2022-2023?”
- “When does Special Term 1 start in academic year 2021-2022?”
- “How many holidays are there in Semester 2 of academic year 2023-2024?”

## How it works

### 1. Load and parse PDFs
All PDFs inside the `academic_calendars` folder are read with `PyPDF2`, and the extracted text is stored in memory.

### 2. Create document summaries
Each full document is passed to an OpenAI chat model to generate a concise summary, with emphasis on the academic year and semester metadata. These summaries are used as the first retrieval layer.

### 3. Chunk documents
Each document is split into fixed-size chunks (default: 1000 characters) for more precise retrieval in the second layer.

### 4. Create embeddings and FAISS indices
The project uses `all-MiniLM-L6-v2` from Sentence Transformers to embed:
- document summaries
- document chunks

FAISS is then used to build vector indices for similarity search.

### 5. Hierarchical retrieval
For each query:
- the system first retrieves the most relevant documents using summary embeddings
- then retrieves the most relevant chunks from those documents
- then sends the retrieved chunks to GPT-4o to generate the final answer
